# Безопасность

## Как сообщить об уязвимости

Через [Security Advisories](https://github.com/akalikbergenov/cyclop/security/advisories/new)
на GitHub — это приватный канал, issue заводить не нужно. Ответ придёт, когда придёт:
проект личный, дежурства по нему нет.

## Поверхность атаки

Её практически нет, и это осознанно.

Cyclop не открывает сетевых портов и не слушает сеть. Единственное, что он
слушает, — локальный сокет вкладки «Claude», и о нём написано отдельно, ниже: это
исключение из обещания, а не деталь реализации. Ни обновлений, ни телеметрии, ни
аналитики. Исходящих соединений два, только по https, и они перечислены здесь,
потому что новое соединение — это отдельное решение владельца, а не деталь
реализации:

- **Курсы валют** для вкладки «Валюта»: раз в час с `cdn.jsdelivr.net`
  (открытые данные [fawazahmed0/exchange-api](https://github.com/fawazahmed0/exchange-api)),
  при недоступности — с `latest.currency-api.pages.dev`. Запрос уходит только
  пока вкладка включена в настройках; выключенная вкладка останавливает и его.
  Ничего о пользователе в запросе нет — это скачивание одного и того же
  публичного файла с курсами.

- **Модели распознавания речи** для вкладки «Встречи»: один раз, по кнопке
  «Скачать модели», с `huggingface.co` (около 600 МБ; модели FluidAudio). Без
  нажатия кнопки не скачивается ничего, и обработка встречи скачивать не умеет.
  Аудио и текст встреч с Mac не уходят никуда.

Всё прочее происходит на одной машине между процессами, которые и так
принадлежат пользователю.

Второе исключение — запись в настройки чужого приложения: одна запись в файле
настроек Claude Code, и только по нажатию кнопки. Оба исключения описаны в
разделе «Вкладка Claude» ниже; решение о них принято в
`docs/adr/0004-claude-requests-are-answered-through-a-hook.md`.

Снимок с айфона попадает на полку через универсальный буфер обмена, то есть
средствами самой macOS: передачу выполняет Continuity, она зашифрована и
подтверждена Apple ID, а Cyclop лишь читает то, что оказалось в буфере. Своего
канала связи с телефоном у него нет.

## Разрешения

При запуске не запрашивается ничего. Вкладка «Встречи» просит два
разрешения, и только когда нажата «Начать запись» в первый раз: **микрофон** и
**запись звука системы** (macOS показывает у второго фиолетовую точку, пока идёт
запись). При первой выгрузке встречи macOS один раз спросит доступ к папке
«Загрузки». Универсального доступа и записи экрана не требуется ни в каком
режиме работы. Вкладка «Claude» не просит у macOS ни доступа к папкам (файлы
Claude Code лежат в `~/.claude`, которую macOS не охраняет), ни разрешений, кроме
одного: **автоматизация** Terminal и iTerm. Её macOS спрашивает один раз, и
только когда нажато «Открыть в Claude» на сессии, которая идёт в одном из них:
Cyclop просит терминал выбрать вкладку, в которой работает процесс этой сессии
(по её tty), и вывести окно вперёд. Из терминалов читается только имя
устройства (tty) каждой вкладки, чтобы найти нужную; ни текст, ни названия
вкладок, ни что-либо ещё, и ничего не сохраняется и не уходит. При отказе
терминал просто выводится на передний план, как раньше. Других приложений
Cyclop не автоматизирует.

Режим «Не спать с закрытой крышкой» вызывает недокументированную функцию ядра
(`kPMSetClamshellSleepState` у корневого домена управления питанием). Прав и
разрешений она не требует и ничего не спрашивает. Но выставленный ею бит живёт
дольше процесса, до следующего запуска Cyclop или перезагрузки: при выходе
приложение его сбрасывает, при сбое остаётся.

## Что Cyclop читает и где это лежит

**Встречи** лежат папками в `~/Library/Application Support/Cyclop/Meetings/`:
звук обеих дорожек, расшифровка и `meta.json`. Звук пишется без сжатия и
остаётся таким, пока не готова расшифровка. Модели распознавания лежат в
`~/Library/Application Support/FluidAudio/`. Эхоподавитель — библиотека и модель
внутри самого приложения. Удаление встречи кладёт папку в Корзину; выгрузка
копирует расшифровку и звук в `~/Downloads`. Подпись приложения нужна стабильная,
иначе разрешения спрашиваются заново (`docs/signing.md`).

**История буфера обмена** живёт только в памяти процесса и не пишется на диск.
Записи с типом `org.nspasteboard.ConcealedType`, которым менеджеры паролей
помечают свои копирования, в историю не попадают вовсе.

**Снимки экрана из буфера** сохраняются файлами в `~/Pictures/Cyclop` и не
удаляются автоматически никогда. Сохраняется всякий скопированный в буфер снимок,
а не только тот, что понадобился, — включая случайно снятое окно банка или
почты. Папка целиком принадлежит пользователю; чистит
её только он. Отключается пунктом меню-бара.

**Полка** хранит в настройках приложения пути к файлам, а не сами файлы.

**Заготовки** лежат в `~/Library/Application Support/Cyclop/snippets.json`
обычным текстом. Файл читается при каждом открытии вкладки и переписывается,
когда заготовку добавляют или удаляют из панели. Для адреса и телефона этого
достаточно; для того, что не должно лежать читаемым, есть менеджер паролей.

**Перевод** выполняется `Translation.framework` полностью офлайн: текст не
покидает машину.

## Вкладка Claude: сокет и запись в настройки Claude

Вкладка показывает сессии Claude Code на этом Mac и позволяет ответить на запрос
(разрешение, вопрос, план) из панели. Чтобы ответ дошёл до процесса Claude Code,
нужна запись в его настройках и сокет, в который эта запись пишет. Нового
разрешения macOS и нового сетевого запроса они не вводят (автоматизация
терминала нужна только кнопке «Открыть в Claude», см. «Разрешения»).

**Сокет.** Пока вкладка включена и Cyclop подключён к Claude, он слушает сокет
Unix `~/Library/Application Support/Cyclop/claude.sock`. Это файл на диске, а не
сетевой порт: по сети до него не достучаться. Права `0600`, то есть только
владелец; у каждого соединения спрашивается пользователь на другом конце, и
чужого отклоняют. Пишет в него ретранслятор — тот же исполняемый файл Cyclop,
запущенный Claude Code с аргументом `--claude-relay`, — а вообще любой процесс
самого владельца; такому процессу и без сокета доступно всё, что доступно
Cyclop. Подделанный запрос показывается в панели только для живой сессии Claude
Code, а ответ уходит только по тому же соединению, по которому пришёл. Запрос
больше 16 МБ отбрасывается. Сокет закрывается, когда вкладку выключают,
приложение завершают или Cyclop отключают от Claude; найденный при запуске
старый сокет заменяется.

**Запись в настройки Claude.** Кнопка «Подключить к Claude» в «Настройках»
добавляет в `~/.claude/settings.json` одну запись: хук `PermissionRequest` без
`matcher`, с одной командой (путь к самому Cyclop и `--claude-relay`) и
таймаутом в сутки. Больше ничего Cyclop в этом файле не меняет, и без нажатия
не трогает его вовсе: ни при запуске, ни когда приложение перенесли в другую
папку. «Отключить от Claude» убирает ровно эту запись. Файл не перекодируется
целиком: правка сохраняет порядок ключей и написание строк и чисел. Если файл не
читается как объект JSON, не записывается ничего, и «Настройки» это говорят.
Перед записью копия файла кладётся в
`~/Library/Application Support/Cyclop/claude-settings-backups/` (последние пять,
права только владельца), проверяется, что файл не менялся с момента чтения, и
новый текст заменяет старый атомарно; символьная ссылка сохраняется, права
файла тоже.

**Что остаётся, если удалить Cyclop подключённым.** Запись указывает на
несуществующий файл: Claude Code пишет ошибку хука на каждый запрос и спрашивает
как обычно, ничего не разрешая само. Поэтому перед удалением нажимают
«Отключить от Claude». Если приложение уже удалено, запись убирают руками:
группу `PermissionRequest`, команда которой оканчивается на `--claude-relay`.
Папка с копиями остаётся на диске, её можно удалить.

**Копии файла настроек Claude** хранят всё, что лежало в файле, включая
переменные окружения и ключи, если они там записаны, — тем же обычным текстом.
Права на копии только у владельца, но это копии чужого файла, и чистит их
владелец.

**Что вкладка читает.** Файлы сессий Claude Code в `~/.claude/sessions/`, по
одному на процесс: имя, папку, состояние, где запущена. Расшифровки разговоров
она не читает. Состояние берётся только оттуда: без подключения вкладка
остаётся списком сессий с кнопкой «Открыть в Claude» (ссылка приложения или
перевод нужного приложения на передний план; для терминала ещё выбор вкладки,
если macOS разрешила автоматизацию).

**Что хранится.** Ничего о запросах не пишется на диск: текст команд, вопросов и
планов живёт только в памяти процесса и пропадает вместе с запросом. Меню-бар
«Скрывать содержимое» умеет закрыть имена сессий и тексты запросов, и закрытый
запрос не отвечается, пока его не покажут (раздел «Claude» там отключён по
умолчанию, как и остальные).
